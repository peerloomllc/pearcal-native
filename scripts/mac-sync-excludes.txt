# What NOT to send to the Mac Mini. One rsync pattern per line; blank lines and
# lines starting with # are ignored (both by rsync --exclude-from and by
# scripts/lib/syncExcludes.js, which reads this same file for the pre-flight).
#
# THIS FILE IS THE ONE SOURCE OF TRUTH. Four call sites used to keep four
# hand-maintained exclude lists that rotted apart (TODO #168): the repo grew
# electron/dist, seeder-launcher/dist and a heap of loose installers, none of
# which any list knew about, so a sync that had to deliver 18 MB walked 18 GB
# and never finished. Add new generated output HERE, not at a call site.
#
# test/macSyncExcludes.test.js fails if any directory in the repo grows past the
# size cap without being covered here, so the rot cannot happen silently again.

# ── Version control and dependency trees ────────────────────────────────────
.git
node_modules

# ── Other platforms' build trees ────────────────────────────────────────────
# Android is built on Linux and never on the Mac. ios/build and ios/Pods are
# generated ON the Mac by pod install; sending ours would clobber the Mac's
# freshly-resolved Podfile.lock, which is the "Check Pods Manifest.lock" failure
# documented in CLAUDE.md.
/android
/ios/build
/ios/Pods

# ios/Podfile.lock is MACHINE-SPECIFIC and must not be pushed. react-native-bare-kit's
# podspec version embeds a hash of the local node_modules ("0.12.2+c51a58" here vs
# "0.12.2+c9a25e" on the Mac), so our lock can never equal the one the Mac's own
# pod install produces. Sending it leaves Podfile.lock != Pods/Manifest.lock and
# every build then dies in "[CP] Check Pods Manifest.lock" with exit 65. The
# Podfile itself DOES sync, so a real dependency change still reaches the Mac and
# `ios-dev-install.sh --pods` regenerates the Mac's lock from it.
/ios/Podfile.lock
